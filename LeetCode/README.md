## 模板

### 1. 差分：区间加 x，最后还原一次

```cpp
// 给 [l, r] 每个数加 x（1-based）
d[l]     += x;
d[r + 1] -= x;
// 所有操作做完后，原地前缀和还原（只做一次！）
for (int i = 1; i <= n; i++) d[i] += d[i - 1];
```

- `d[i] = a[i] - a[i-1]`，记的是**差值**
- 原数组 = 差分数组的前缀和
- 数组至少开 `n + 2`（`r + 1` 会越界）
- **右端点是否包含**决定用 `r + 1` 还是 `r`：
  - 区间 `[l, r]` 两端都算 → `d[r + 1] -= x`
  - 实际占 `[l, r-1]`（如拼车的下车点）→ `d[r] -= x`

### 2. 前缀和：区间查询 O(1)

```cpp
// 一维：pre[i] = a[1] + ... + a[i]
long long s = pre[r] - pre[l - 1];

// 二维（哨兵版，零 if）
pre[i][j] = pre[i-1][j] + pre[i][j-1] - pre[i-1][j-1] + matrix[i-1][j-1];
//                                               ↑ 这一项最常漏
long long s = pre[r2+1][c2+1] - pre[r1][c2+1] - pre[r2+1][c1] + pre[r1][c1];
```

- **需要写边界 if，说明哨兵没开**（多开一行一列全 0）
- 前缀和一律 `long long`

### 3. 二分答案：外层固定，只换 check

```cpp
int lo = 下界, hi = 上界;
while (lo < hi) {
    int mid = lo + (hi - lo) / 2;
    if (check(mid)) hi = mid;        // 可行 → 往小逼（保留 mid）
    else            lo = mid + 1;    // 不可行 → 往大逼（排除 mid）
}
return lo;
```

- **可行往小逼，不可行往大逼**（唯一要记的判定规则）
- 二分答案是"逼近边界"，不是"找目标"，**不能在循环里 `return`**
- 下界移动必须写 `lo = mid + 1`，写 `lo = mid` 会死循环

### 4. 回溯：DFS + 撤销选择

```cpp
// A 型：要全部解 —— void + 成员容器累积
void dfs(参数) {
    if (出口) { ret.push_back(path); return; }
    for (每个候选) {
        if (不可选) continue;
        做选择;
        dfs(下一层);
        撤销选择;                 // ← 灵魂
    }
}

// B 型：要一个解 —— bool 返回值一层层往上抛
bool dfs(参数) {
    if (出口) return true;
    for (每个候选) {
        if (不可选) continue;
        做选择;
        bool 通 = dfs(下一层);    // ① 必须用变量接住
        撤销选择;                 // ② 先恢复现场
        if (通) return true;      // ③ 再往上抛
    }
    return false;                 // ④ 兜底不能漏
}
```

**"选择"的四种形态**（看题面就能定循环起点和判据）：

| 形态 | 每层的"选择" | 循环从哪开始 | 约束 | 例题 |
|---|---|---|---|---|
| 排列 | 选一个没用过的数 | `0` | `visit` 数组 | 46 / 47 |
| 组合 | 选一个下标 ≥ `start` 的数 | `start` | 不需要（`start` 天然去重） | 39 / 40 |
| 棋盘 | 这一行皇后放哪列 | `0` | 三约束数组 | 51 |
| 网格 | 往上下左右哪格走 | 4 个方向 | 越界 + 字符 + `visit` | 79 |

**去重判据会随题型变形**（最容易照搬出错）：

```cpp
// 排列（层边界是 0）
if (i > 0     && nums[i] == nums[i-1] && !visit[i-1]) continue;
// 组合（层边界是 start）
if (i > start && nums[i] == nums[i-1])                continue;
```

语义固定："我和前一个值相同，而前一个**在本层还没被选走** → 同一批候选，只用第一个。"
**变的只是"本层的边界在哪"。**

**B 型四条铁律**：① 返回值必须用变量接住；② 撤销排在 `return true` 之前；
③ 兜底 `return false` 不能漏；④ 别想用参数（按值传递）把结果带回去。

## 通用技巧与坑

| 技巧 / 坑 | 说明 |
|---|---|
| 向上取整 | `(a + b - 1) / b`，等价于 `ceil(a / b)`；**两个 int 相除是截断除法** |
| 强制转换 | `(double)a / b` 得浮点；`(double)(a / b)` 先整数除完再转，小数早丢了 |
| 哨兵 | 加法单位元 0，乘法单位元 1；把"不存在的部分"变成"值为 0/1 的合法部分" |
| 数据类型 | 前缀和、累加、计数默认 `long long`；`int` 上限约 2.1×10⁹ |
| 复杂度估算 | C++ 约 10⁸ 次操作/秒；超过就要换思路（蓝桥杯按测试点给部分分，能提前判断超时很关键） |
| `memset` | 参数顺序是 `(指针, 值, 字节数)`；只对 0 和 -1 安全；初始化建议直接 `int a[N] = {0};` |
| `INT_MAX` | 求最小值时用 `INT_MAX` + `min()`；求最大值时用 `INT_MIN`（或 0）+ `max()`，**起手值和累积函数必须配对** |
| 两种二分写法 | 逼近式（`while(lo<hi)` + `hi=mid`，本文所用）与查找式（`while(l<=r)` + `r=mid-1`，返回 `l`）；前者不易错 |
| 离散化二分 | 答案范围极大时，先收集所有候选值去重排序，在**下标**上二分；注意 `lo`/`hi` 是下标、`mid` 是值，两者不能混 |
| `unordered_map::operator[]` | 读一个不存在的键会**插入**一个值为 0 的项。实测：`m[0]=1` 时 `size=1`，仅"读"一次 `m[-5]` 后 `size=2`。只想读、不想改容器，请用 `count()` / `find()` |

## 错题本（反复出现的问题）

### 边界六类错（截至 2026-09-16）

> 已犯的每一类都记在下面。**开数组前先把最大下标算出来写下来** —— 这是唯一的解药。

**① 下标偏移** —— 1-based / 0-based 混用
- LC 40：去重判据的层边界写 `i > 0`，应为 `i > start`（照搬排列出错）
- 教训：判据的**语义**固定，**边界基准**随题型变（排列是 0，组合是 start）

**② 数组大小错** —— 按「操作条数」而非「位置个数」开，或直接写魔数不先算最大下标
- LC 1109：`i < n` 遍历航班数而非预订记录数，应 `bookings.size()`
- LC 1094：`diff(trips.size()+1)`，站点范围 0~1000，应开 1001/1002
- LC 51：`diag2[10]`，`r+c` 最大 `2n-2`，n≥6 越界

**③ 起手值与累积函数不配对**
- LC 410：`lo = INT_MAX` 配 `max()` → 恒为 INT_MAX，循环跑完什么都没变

**④ 改动不成组** —— 改了一处没改另一处
- LC 410：`sum = e` 加了，`sum += e` 没挪进 `else`，元素被算两次

**⑤ 抄了剪枝/优化没抄前提**
- LC 39：`break` 剪枝依赖数组升序，漏 `sort` 直接失效
  （实测 `[8,7,4,3], 11` → 漏 sort 输出 0 个，正确 3 个）

**⑥ 容器初始化填错值**
- LC 51：`board[i].resize(n)` 填 `'\0'` 不是 `'.'`（实测 n=4 输出 `'\x00Q\x00\x00'`）
- LC 1094：`memset(num, sizeof(num), 0)` 参数顺序写反

### 其他反复出现的问题

1. **递推式漏加当前元素** —— LC 304（漏 `matrix[i][j]`）、LC 974（`dp[i] += dp[i-1]` 漏 `nums[i]`）
2. **漏掉边界 / 空前缀** —— LC 974、LC 560 漏 `hash[0] = 1`（09-15 小测暴露）
3. **原地修改破坏原始数据** —— LC 1094 在循环里反复做前缀和，第二次操作全错
4. **概念混用** —— LC 40 组合题里加 `visit`，恒为 `false` 的死代码
   （排列用 `visit`，组合用 `start`）
5. **误用记忆化** —— LC 79：`memo[i][j]` 还取决于 `visit` 集合，
   状态描述不完整就不能记忆化。判断标准：**同一状态答案是否唯一**
6. **递归返回值不接** —— LC 79：单独写 `dfs(...)` 等于扔掉结果；
   也别用 `bool flag` 参数回传（按值传递改的是副本）

### 有效的验证手段

收录进本仓库的每题，改动后都用一组用例实测过（含回归用例）：
LC 51 用 `n=6` 复现原越界、LC 40 用 `[1,1,1]/2` 复现原漏解、
LC 39 用 `[8,7,4,3]/11` 复现原剪枝失效。**改完必跑，别靠看。**

**随机对拍**是比单点用例更强的验证：LC 560 对拍 2000 组（vs 哈希暴力）、
LC 410 对拍 1500 组（vs 区间 DP），全部零不一致。

> ⚠️ **但对拍有个前提：基准必须先自证。**
> 给 LC 410 写对拍时，基准里的前缀和自己写错了下标
> （`pre[i] = pre[i-1] + nums[i]`，应为 `nums[i-1]`），
> 结果 1500 组里报了 1122 组"不一致"，差点误判成被测代码有 bug。
> 加了 `brute` 自检（先让它算官方示例的 18/9/4）才定位到是自己的问题。
> **基准不自证正确，对拍就是循环论证。**
