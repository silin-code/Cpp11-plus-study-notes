## 模板

### 1. 差分：区间加 x，最后还原一次

```cpp
// 给 [l, r] 每个数加 x（1-based）
d[l]     += x;
d[r + 1] -= x;
// 所有操作做完后，原地前缀和还原（只做一次！）
for (int i = 1; i <= n; i++) d[i] += d[i - 1];
```

- `d[i] = a[i] - a[i-1]`，记的是**差值**
- 原数组 = 差分数组的前缀和
- 数组至少开 `n + 2`（`r + 1` 会越界）
- **右端点是否包含**决定用 `r + 1` 还是 `r`：
  - 区间 `[l, r]` 两端都算 → `d[r + 1] -= x`
  - 实际占 `[l, r-1]`（如拼车的下车点）→ `d[r] -= x`

### 2. 前缀和：区间查询 O(1)

```cpp
// 一维：pre[i] = a[1] + ... + a[i]
long long s = pre[r] - pre[l - 1];

// 二维（哨兵版，零 if）
pre[i][j] = pre[i-1][j] + pre[i][j-1] - pre[i-1][j-1] + matrix[i-1][j-1];
//                                               ↑ 这一项最常漏
long long s = pre[r2+1][c2+1] - pre[r1][c2+1] - pre[r2+1][c1] + pre[r1][c1];
```

- **需要写边界 if，说明哨兵没开**（多开一行一列全 0）
- 前缀和一律 `long long`

### 3. 二分答案：外层固定，只换 check

```cpp
int lo = 下界, hi = 上界;
while (lo < hi) {
    int mid = lo + (hi - lo) / 2;
    if (check(mid)) hi = mid;        // 可行 → 往小逼（保留 mid）
    else            lo = mid + 1;    // 不可行 → 往大逼（排除 mid）
}
return lo;
```

- **可行往小逼，不可行往大逼**（唯一要记的判定规则）
- 二分答案是"逼近边界"，不是"找目标"，**不能在循环里 `return`**
- 下界移动必须写 `lo = mid + 1`，写 `lo = mid` 会死循环

### 4. 回溯：DFS + 撤销选择

```cpp
// A 型：要全部解 —— void + 成员容器累积
void dfs(参数) {
    if (出口) { ret.push_back(path); return; }
    for (每个候选) {
        if (不可选) continue;
        做选择;
        dfs(下一层);
        撤销选择;                 // ← 灵魂
    }
}

// B 型：要一个解 —— bool 返回值一层层往上抛
bool dfs(参数) {
    if (出口) return true;
    for (每个候选) {
        if (不可选) continue;
        做选择;
        bool 通 = dfs(下一层);    // ① 必须用变量接住
        撤销选择;                 // ② 先恢复现场
        if (通) return true;      // ③ 再往上抛
    }
    return false;                 // ④ 兜底不能漏
}
```

**"选择"的四种形态**（看题面就能定循环起点和判据）：

| 形态 | 每层的"选择" | 循环从哪开始 | 约束 | 例题 |
|---|---|---|---|---|
| 排列 | 选一个没用过的数 | `0` | `visit` 数组 | 46 / 47 |
| 组合 | 选一个下标 ≥ `start` 的数 | `start` | 不需要（`start` 天然去重） | 39 / 40 |
| 棋盘 | 这一行皇后放哪列 | `0` | 三约束数组 | 51 |
| 网格 | 往上下左右哪格走 | 4 个方向 | 越界 + 字符 + `visit` | 79 |

**去重判据会随题型变形**（最容易照搬出错）：

```cpp
// 排列（层边界是 0）
if (i > 0     && nums[i] == nums[i-1] && !visit[i-1]) continue;
// 组合（层边界是 start）
if (i > start && nums[i] == nums[i-1])                continue;
```

语义固定："我和前一个值相同，而前一个**在本层还没被选走** → 同一批候选，只用第一个。"
**变的只是"本层的边界在哪"。**

**B 型四条铁律**：① 返回值必须用变量接住；② 撤销排在 `return true` 之前；
③ 兜底 `return false` 不能漏；④ 别想用参数（按值传递）把结果带回去。

### 5. 网格 DFS 的两套调用约定（**必须全程一致，不能混用**）

| | **模式 A「调用者标记」** | **模式 B「自足式」** |
|---|---|---|
| 谁标记 `(i,j)` | 上一层调用者 | **dfs 自己** |
| dfs 开头 | 直接遍历邻居 | 先判自己（越界 / 非陆地 / 已访问 → 返回 0） |
| 多方向合并 | 循环内可 `return`（若不需要收齐） | **不可**在循环内 `return` |
| 例子 | LC 79 / LC 200 / LC 695（本仓库版） | LC 695 的另一种写法 |

**混用的后果（LC 695 实测）**：外层用了 A 的 `use[i][j]=true`，
dfs 里又用 B 的「检查自己」守卫 → 守卫必然命中 → **dfs 恒返回 0**。

> 一句话：**要么调用者标记、dfs 不检查自己；要么 dfs 自己标记、调用者别插手。**
> 换题时不能只改类型不改约定。

### 7. 记忆化搜索（DFS + 记表 = 自顶向下 DP）

**先过这一关：同一状态，答案是否唯一？**

| | 状态唯一？ | 能否记忆化 |
|---|---|---|
| LC 79 单词搜索 | ❌ `memo[i][j]` 还取决于"走过哪些格子"（visit 集合） | **不能** |
| LC 329 最长递增路径 | ✅ `f(i,j)` 只取决于 `(i,j)` 自己 | **能** |

```cpp
int dfs(i, j) {
    if (memo[i][j] != 哨兵) return memo[i][j];   // ① 先查表
    ... 递归取 max / sum，得到结果 ...
    memo[i][j] = 结果;                            // ② 算完存表
    return memo[i][j];
}
```

- **哨兵值必须"不可能是合法答案"**（本题最短是 1 → `-1` / `0` 都安全）
- 递归的"出口"就是**走不动了**（本题没有合法邻居 → 返回 1）
- **什么时候不需要 visit**：题目约束本身保证无环时（如"只能往**值更大**的格子走"）
  → 图是 DAG → DFS 必然终止，不用任何防回头机制
- 等价写法：把状态按依赖顺序排好、自底向上直接 DP（329 / 2328 可用"按值从大到小"），
  可拿它当独立对拍基准
- ⚠️ **约束里的"等号"不是小事**：题目说"**严格**递增"时，条件必须写 `<` 而不是 `<=`。
  放宽成 `<=` 会让相邻的**等值**状态**互相指向 → 出现环 → 记忆化直接失效**
  （`memo` 是递归返回**之后**才写回的，有环就永远回不来）。
  → **那条"严格"约束，同时也是"这题可以记忆化"的前提。**
- ⚠️ **"出口"的形态因题而异**（最容易照搬上一题而写错的一处）：

  | 题 | 出口是什么 | 怎么处理 |
  |---|---|---|
  | LC 329 / 2328 | **走不动了**（没有合法邻居） | 返回 1（那一格自己也算一条） |
  | LC 576 | **"走出边界"这个动作本身** | 在动作发生的那一步**当场记账**（+1），**不**继续递归 |

  照搬 329 的出口去写 576，就会写成"统计**留在**界内的走法数"——正好是答案的反面。
  一句话记：**每一步都有两个命运 ——"出去了"（记账）或"还在里面"（继续）。**
- **状态的形态不止"坐标"一种**。已见过的几种：

  | 形态 | 例子 |
  |---|---|
  | 坐标 | LC 329 / 2328 |
  | 坐标 + 额外维度 | LC 576（`+剩余步数`） |
  | **区间 `[l, r]`** | **LC 486** |
  | **位掩码（状压）** | **LC 464** |

  判据始终是那句：**"决定答案的最小信息是什么"**。
- **"能不能"（存在性）vs "有多少种"（计数）—— 决定要不要收齐所有分支**：
  - **存在性**（LC 464：能不能赢）→ **找到一个成功分支就可以立刻 `return`**，剩下的不用试
  - **计数**（LC 2328：有多少条路径）→ **必须把所有分支的贡献全收齐**再返回
  - 同样在 `for` 循环里，一个能提前收工、一个不能 —— 想清楚题目问的是哪一种。
- **博弈类（双人最优）：用「分差」，不要用「总分」**（LC 486）。
  因为只有分差能让**对手的最优解直接减过来**：我取 x 之后的净分差 = `x − f(剩下那段)`。
  记总分就要同时追踪两个人的分数 → 状态爆炸。
- **`f` 里不要出现"轮到谁"这个参数**（LC 486）：`f` 永远描述"**当前要动手的人**"，
  递归下去时对手就成了那个人 —— **同一个函数换个人用**。
- **选项数量固定时，别用累加器**（LC 486）：只有两个选择就直接 `max(两项)`。
  用累加器就多出"起手值选什么"的问题 —— 而**起手值选错是错误类 ③**（见错题本）。

### 8. 并查集（Union-Find）

**零件库**：`Algorithm/Lanqiao_competiotion/UF.hpp`
—— 实现的是**约定 2（根存负数）**：`UnionFind`，带按大小合并 + 递归 find，
另有 `countSets()`（数集合个数）。实测 n=200000 无栈溢出。
（约定 1（根自指）的写法见下面这张对照表 —— 需要时按表另写一个类即可。）

**先说清楚：有【两套约定】，都正确，但绝不能混用**（详见错题本第 13 条）

| | **约定 1：根自指**（本项目统一用） | **约定 2：根存负数**（中文教材 / 408 常用） |
|---|---|---|
| 初始化 | `p[i] = i` | `p[i] = -1` |
| 判根 | `p[i] == i` | `p[i] < 0`，且 `-p[i]` = 集合**大小** |
| `find` 循环条件 | `while (p[x] != x)` | `while (p[x] >= 0)` |
| 合并 | `p[find(a)] = find(b);` | `p[ra] += p[rb]; p[rb] = ra;`（顺手完成按大小合并） |

**三个易错位点**

| # | 位点 | 判据 |
|---|---|---|
| ① | **数根** | 自指约定必须 `p[i] == i`（不是 `e < 0`，那是负数约定的写法） |
| ② | **遍历范围** | 邻接矩阵**对称**，只需上三角（`j` 从 `i+1` 起） |
| ③ | **`find` 终止条件** | 是 `p[x] == x`，**不是 `x > 0`** —— 根不一定是下标 0 |

**路径压缩的两种写法**

| | 写法 | 取舍 |
|---|---|---|
| 递归 | `if (p[x] == x) return x;`<br>`return p[x] = find(p[x]);` | 最短、最直观；**有栈深限制** |
| **循环**（零件库用） | 第一趟找根，第二趟把路上每个点挂到根 | 稍长，但**不怕深** |

**实测（10-02）**：手工造 n = 100000 的长链（`unite(i, i+1)`，不做按秩合并时树退化成链），
**递归版 `find(0)` 栈溢出（`0xC00000FD`），循环版正常**。
→ 这也正是 408 考「按秩合并 / 路径压缩对**树高**的影响」的实际意义：
`unite` 里加一句"小树挂大树"，树高就压到 `O(log n)`，递归版也就安全了。

**三种典型用法**（对应本周三道题）

| 用法 | 题 |
|---|---|
| 数一共有几个组 | LC 547 省份数量 |
| 先合并所有等式，再逐个验证不等式 | LC 990 等式方程的可满足性 |
| 动态逐条加边，加之前先问"两端是否已同根" | LC 684 冗余连接 |

**「两趟」判据**（LC 990）：当约束分两类、且**一类依赖另一类**时，分两趟走 ——
第一趟只"**建立**关系"（`==` → `unite`），第二趟只"**检验**关系"（`!=` → 查 `same`）。
按数组顺序一趟走完会变成**顺序依赖**：实测 `["a==b","b!=c","c==a"]` 单趟答 true（应 false），
`["a!=b","a==b"]` 单趟也漏检。

**字符串方程的下标坑**（LC 990）：`"a==b"` 和 `"a!=b"` 的 **`e[2]` 都是 `'='`**，
符号位在 **`e[1]`**。写 `if (e[2] == '=')` 会对**所有**方程成立 → 所有 `!=` 被当成 `==` 合并，
检查分支永不执行 → 恒返回 true。

### 9. 单调栈（求「右边第一个更大 / 更小」）

**母题**：LC 739 每日温度 —— 对每个 `i`，找右边第一个比它大的位置。

**两步结构**（后面所有单调栈题都是这个骨架）

```cpp
for (int i = 0; i < n; i++) {
    while (!st.empty() && temperatures[i] > temperatures[st.top()]) {
        ret[st.top()] = i - st.top();       // i 就是栈顶那位的答案
        st.pop();
    }
    st.push(i);                             // 无条件 push，全循环【只此一处】
}
```

**核心判据（Week 5 的主线问题）**：

> **什么时候，栈里那些候选可以被扔掉？**
> 本题：**新来的比栈顶热** → 栈顶那位的答案就是 `i`，它以后再也没用了。

**三条要点**

| # | 要点 | 为什么 |
|---|---|---|
| ① | **栈里存下标**（不存值） | 答案要的是"等了几天" = `i - j`，只存值就不知道是哪天了 |
| ② | **用 `while` 不是 `if`** | 一次可能连弹好几个（LC 739 的 i=5 连弹 2 个、i=6 连弹 2 个） |
| ③ | **push 只一处、且无条件** | `i` 自己永远要进栈（它也在等答案）；"栈空则 push"只是它的特例 |

**易错点（LC 739 实测踩过，且能骗过递减用例）**

| # | 错法 | 后果 |
|---|---|---|
| ① | `st.top() < temperatures[i]` | **左边是下标、右边是温度** → `0 < 73` 恒成立 → 每轮弹空整个栈 → 答案**全 0** |
| ② | `while (st.size())` 少条件 | 把**整个栈弹空**，而不是"弹到栈顶不比当前小为止" |
| ③ | 三段式（`if 栈空 push` / `if 比较` / `else if push`） | **两个 push 点**：同一个 i 可能进栈两次；"相等"时两分支都不走 → i 丢失 |

**「能过 ≠ 对」第 5 种形态**：若输入是**单调不增**或**全相等**，正确答案本来就是全 0 ——
错法①的版本**恒输出全 0**，会**通过**这些用例。官方示例是递增的才暴露。

**循环数组怎么处理（LC 503）**

把数组**接长一倍**（`tmp = nums + nums`，长度 `2n`），在 `tmp` 上跑同一套单调栈，
最后**只取前 `n` 个**答案 —— 环形问题一步化成线性。

| 要点 | 说明 |
|---|---|
| 为什么 `2n` 够 | 位置 `j` 最多要看它后面 `n-1` 个 → 虚拟下标最大 `2n-2`，落在 `tmp` 内 ✓ |
| 等价写法 | 不复制数组，用 `nums[i % n]` 取数（**省 O(n) 空间**） |
| 别忘 | 结果要**截取前 n 个**；第二轮的下标也会进栈/被算答案，无害但要丢掉 |

**"栈里存什么"的三次变化**（同一个骨架、三种选择）

| 题 | 栈里存 | 弹出时记 |
|---|---|---|
| 739 | **下标** | 距离 `i - j` |
| 496 | **值** | 答案值 `nums[i]` |
| 503 | **下标** | 答案值（要写 `ret[st.top()]`，所以需要下标） |

> 判据：**栈里存什么，取决于"题目最后要的是什么"** —— 要位置/距离就存下标，只要值就可以存值。

## 通用技巧与坑

| 技巧 / 坑 | 说明 |
|---|---|
| 向上取整 | `(a + b - 1) / b`，等价于 `ceil(a / b)`；**两个 int 相除是截断除法** |
| 强制转换 | `(double)a / b` 得浮点；`(double)(a / b)` 先整数除完再转，小数早丢了 |
| 哨兵 | 加法单位元 0，乘法单位元 1；把"不存在的部分"变成"值为 0/1 的合法部分" |
| 数据类型 | 前缀和、累加、计数默认 `long long`；`int` 上限约 2.1×10⁹ |
| 复杂度估算 | C++ 约 10⁸ 次操作/秒；超过就要换思路（蓝桥杯按测试点给部分分，能提前判断超时很关键） |
| `memset` | 参数顺序是 `(指针, 值, 字节数)`。**它按【字节】填充**：只有"**每个字节都相同**"的值才安全 —— `0x00`(=0)、`0xFF`(=-1)、`0x3F`(=`0x3f3f3f3f`，一个很大的正数)。**`INT_MIN` 不能用它填**（实测 `memset(m, INT_MIN, sizeof m)` 得到 `0 0 0 0`，因为只取最低字节 0x00）。初始化非 0/-1 的值，请用**循环赋值**或 `vector` 构造函数 |
| `INT_MAX` | 求最小值时用 `INT_MAX` + `min()`；求最大值时用 `INT_MIN`（或 0）+ `max()`，**起手值和累积函数必须配对** |
| 两种二分写法 | 逼近式（`while(lo<hi)` + `hi=mid`，本文所用）与查找式（`while(l<=r)` + `r=mid-1`，返回 `l`）；前者不易错 |
| 离散化二分 | 答案范围极大时，先收集所有候选值去重排序，在**下标**上二分；注意 `lo`/`hi` 是下标、`mid` 是值，两者不能混 |
| `unordered_map::operator[]` | 读一个不存在的键会**插入**一个值为 0 的项。实测：`m[0]=1` 时 `size=1`，仅"读"一次 `m[-5]` 后 `size=2`。只想读、不想改容器，请用 `count()` / `find()` |
| **滑动窗口的成立条件** | 需要"窗口和随窗口扩大**单调变化**"。全正数成立（LC 209）；**有负数就失效**（LC 53 不能用双指针）。判据：拿到题先看有没有负数 |
| **前缀和最值** | 固定一端后，另一端的最优值可**增量维护**，于是不必枚举：`max(pre[i] - min(pre[0..i-1]))`。与 DP 的"最优子结构"是同一件事（LC 53 两版数学等价，3000 组实测零不一致） |
| **树上前缀和** | 和数组版同源，但**必须回溯撤销**：进入 `hash[cur]++`、离开 `hash[cur]--`。因为哈希表代表的是「当前路径的状态」——路径退回去，状态也要退回去。另：`hash[0]=1` 不能漏，否则**从根开始的路径全部漏掉**（LC 437） |
| **多源 BFS** | 起点是**一批**时，把全部起点一次入队，BFS 天然并行推进（逐个源跑再合并会很麻烦）。计时用「层」：外层 `while(!q.empty())` 一轮 = 一层，内层先 `int size=q.size()` 只处理本层，新推入的留到下一轮。**第 0 层（初始源）不算时间** → 要"本层真扩散才 `ret++`"，否则普遍多 1（LC 994 实测：应 4 得 5）。两种问法：**(a) 求"最晚那一层"** → 层 = 时间，注意第 0 层不算（LC 994）；**(b) 求"每格在第几层被覆盖"** → 层号直接就是距离，源自身 = 0（LC 542）。**入队即标 visited**，否则重复入队会膨胀 |
| **用「改值」兼当 visited** | 访问过的格子直接改成目标值，之后用"值 == 原值"判断"没访问过" → 省掉一个 visited 数组（LC 733）。**两个前提**：① 开跑前先把原值存下来；② **若"目标值 == 原值"，标记会失效 → 必须在开头早退**，否则同一格被反复入队、死循环 |
| **返回二维数组时不要预开** | 别 `resize(2000)` 再截断（魔数 + 易漏截断）。改成**每层 / 每段开始时先 `ret.push_back(vector<int>())` 长出一行，再用 `ret.back().push_back(v)` 填** —— 长度天然精确、无魔数、无需 resize（LC 102）。`back()` 写法还能省掉手动的层下标变量 |
| **同量级优化：两趟 DP 代 BFS** | 求"网格每格到最近 0 的距离"时，BFS 已是 O(n·m) 下界，但**两趟扫描**（左上→右下，再右下→左上）同量级、额外空间 O(1)、**实测快约 2.4 倍**（LC 542）。原理：无墙网格最短路 = 曼哈顿的单调路径，而单调路径可重排成「先下/右、后上/左」，两趟正好覆盖。**有墙则不成立** → 必须 BFS。同理可推广到"到最近某种格子的距离"类题 |
| **状态设计三步**（通用） | ① 问「**往后会发生什么，由什么决定？**」② 把候选信息分成「必须交代的**前提**」/「能被算出来的**答案**」（后者不进状态）③ 剩下的就是状态。<br>**实例**：LC 464 → "哪些数被拿走"；LC 1349 → "**排第 r 行只需要知道第 r-1 行怎么坐的**" ⇒ 状态 =（行号，这一行的坐法）。<br>**推论**：mask 的**语义可以换**（"选了哪些元素" / "一排位置的状态"），但"用一个整数装一排东西"的用法完全一样 |
| **集合运算 → 位运算 对照**（背下来） | 并集 `A\|B`　交集 `A&B`　差集 `A&~B`　**子集 `(A&B)==A`**　**不相交 `(A&B)==0`**　空集 `A==0`。把集合压成 mask 后，**集合运算就是一次位运算**。位号约定 `c-'a'`（字符）/ `i`（元素） |
| **位运算的优先级低于比较**（必背） | `&`、`\|`、`^` 的优先级都**低于** `==`、`!=`、`<`、`>`。**位运算和比较混用时，位运算必须自己加括号**：<br>`if ((m[i] & m[j]) == 0)` ✅　／　`if (m[i] & m[j] == 0)` ❌（被解析成 `m[i] & (m[j] == 0)`）<br>LC 318 与 LC 464 都在这附近栽过 |
| **`>> 1;` / `+ 1;` 单独成句 = 什么都没干** | `x >> 1` 单独一行只是"算了然后扔掉"，**x 一点没变** → 循环里就是**死循环**。要改就写 `x >>= 1`；只想看一眼就必须把结果用掉。**已犯两次**（printBinary 的 `x >> 1;`、LC 318 的 `cur1 >> 1;`）。编译开 `-Wall` 会报 `statement has no effect` |
| **什么时候必须用 mask 表示集合** | 当集合需要**预先存起来、反复两两比较**时。例：LC 318 比较所有单词两两有无公共字母 → 逐字符比 `O(n²×26)`，预压成 mask 后每对只要一次 `&` → `O(n²+L)`。**比较次数多到"不值得每次重算集合"时，就用 mask 预存。** 反过来（LC 1684 只比一次）用"逐字符检查 + 早退出"反而更好 |
| **类内成员不能用 `()` 给初值** | `vector<int> v(3,0);` 写在**函数里**合法；写在**类内当成员**就**编译不过** —— C++ 会把 `v(3,0)` 当**函数声明**解析，报 `error: expected identifier before numeric constant`。类内只能写 `=` 或 `{}`；**最稳的做法是成员只声明、在入口函数里 `assign` / 循环赋值**（顺带也解决了"成员没复位"的问题） |
| **成员容器必须在入口复位** | 成员是"**每次调用新建对象**"时才干净的。若同一个对象被连续调用（本地多测 / 调试连调），上一轮的残留值会被当成本轮的结果读出来。**实测 LC 486：同一对象连调 2000 次，分差算错 1237 次（62%）**。纪律：入口第一件事 `assign()` / `clear()`（LC 46 / LC 200 / LC 486） |
| **能不能记忆化？看「状态是否唯一」** | `memo[i][j]` 的答案若**还依赖"怎么走到这儿的"**（如 LC 79 的 visit 集合）→ 状态不唯一 → **不能**记忆化；只依赖 `(i,j)` 自己（如 LC 329）→ 能。另：题目约束若天然保证无环（"只能往值更大走"），连 visit 都省了 |
| **「过了」≠「对」：输出量越粗越能藏错** | 模型只要输出量足够粗，错误的**方向 / 假设**就可能被掩盖：LC 207 只问"有没有环" → **建图反了照样过**（实测对拍 5000 组零错）；LC 210 要具体顺序 → 立刻露馅（同一张反图推顺序，60% 非法）。**验模型的办法：拿去解要求更细的姊妹题。** 同理：只跑官方示例不算验证，**随机对拍 + 姊妹题**才算 |
| **「过了」≠「对」：靠数学巧合对** | 第二种藏错方式：**代码写错了，但结果恰好对**。LC 78：`mask += i` 得到的是**三角数** `T_i=i(i+1)/2`（0,1,3,6,10,15,21,28…），而不是 `0..2ⁿ-1`；但 **`T_i mod 2ⁿ` 恰好是 `0..2ⁿ-1` 的一个排列**（n=1..16 验证成立），而 `mask & (1<<i)` 只看低 n 位（等价取模）→ **结果集合完全正确，能 AC**。改成 `mask += 1` 同样能 AC。**判据：代码里"你说不清为什么对、但结果对"的部分 = 定时炸弹**——循环起点/检查方式/范围一改就全错。**「能过」不是标准，「我能说清它为什么对」才是。** |
| **「过了」≠「对」：错解恒等于「特殊输入」的正确答案** | 第三种藏错方式：错误的版本，对**某一类输入**恰好给出正确答案。**LC 739**：比较对象写错（`st.top()` 既是下标又被当温度用）的版本**恒输出全 0**；而**单调不增**（`[90,80,70]`）或**全相等**（`[30,30,30]`）的输入，正确答案本来就是全 0 → **这些用例会通过**（实测两组都 OK），但递增输入立刻全错。**判据：不要只用一类数据验证**——官方示例往往只覆盖一种形态，自己造一组"相反形态"的输入 |
| **「过了」≠「对」：答案全对，但资源崩** | 第四种：**正确性没问题，性能/健壮性坏了**。**10-07 实测**：并查集把"按大小合并"写成"按下标合并"（`f1 > f2` 应为 `p[f1] > p[f2]`）→ 答案**全对**，但树高退化成 `O(n)`（n=2000 时深度 1999）→ 递归 `find` **栈溢出 `0xC00000FD`**。在 LeetCode 的小数据上**照样 AC**，只有 `n = 10^5` 级输入才炸 |

## 错题本（反复出现的问题）

### 边界六类错（截至 2026-09-16）

> 已犯的每一类都记在下面。**开数组前先把最大下标算出来写下来** —— 这是唯一的解药。

**① 下标偏移** —— 1-based / 0-based 混用
- LC 40：去重判据的层边界写 `i > 0`，应为 `i > start`（照搬排列出错）
- 教训：判据的**语义**固定，**边界基准**随题型变（排列是 0，组合是 start）

**② 数组大小错** —— 按「操作条数」而非「位置个数」开，或直接写魔数不先算最大下标
- LC 1109：`i < n` 遍历航班数而非预订记录数，应 `bookings.size()`
- LC 1094：`diff(trips.size()+1)`，站点范围 0~1000，应开 1001/1002
- LC 51：`diag2[10]`，`r+c` 最大 `2n-2`，n≥6 越界
- **LC 684（10-02）**：`p.assign(n,-1)` —— 节点编号是 **1..n**（1-based），却按【边数】开数组
  → 访问 `p[n]` 越界。**实测两个官方用例都返回了正确答案**（越界那一格恰好可读可写，
  "冒充"成了第 n+1 个元素）；加边界探针后真相是**越界读 8 次、越界写 2 次**，
  把 `p[x]` 换成受检访问（越界时假设读到 -1）答案就变成 `[0,0]`（错）。
  → **同一份逻辑、两种环境、两个不同答案 = 未定义行为**。
  **判据：开数组前问一句"这个数组的下标最大能取到几？"** ——
  这里下标是**节点编号**（1..n），不是**边的序号**（0..n-1）。

**③ 起手值与累积函数不配对**
- LC 410：`lo = INT_MAX` 配 `max()` → 恒为 INT_MAX，循环跑完什么都没变

**④ 改动不成组** —— 改了一处没改另一处
- LC 410：`sum = e` 加了，`sum += e` 没挪进 `else`，元素被算两次

**⑤ 抄了剪枝/优化没抄前提**
- LC 39：`break` 剪枝依赖数组升序，漏 `sort` 直接失效
  （实测 `[8,7,4,3], 11` → 漏 sort 输出 0 个，正确 3 个）

**⑥ 容器初始化 / 复位错**
- LC 51：`board[i].resize(n)` 填 `'\0'` 不是 `'.'`（实测 n=4 输出 `'\x00Q\x00\x00'`）
- LC 1094：`memset(num, sizeof(num), 0)` 参数顺序写反
- LC 200：`use.resize(n, vec(m, false))` —— **尺寸不变时 `resize` 不重置任何元素**。
  实测同一对象连调 3 次 → `2 / 0 / 0`（应为 2/2/2）；先跑 2×3 再跑 1×1 → `1 / 0`。
  力扣每用例新建对象所以不触发，**本地多测 / 调试连调必错**。改用 `assign`
- LC 46：成员 `ret` / `path` 没清空，本地连调会累积结果（同一毛病的首次出现）
- LC 102：`ret.resize(2000)` **预开一大块、返回前忘了截断** → 层级内容全对，
  但多出 1995 行空行 → WA（力扣按精确输出比对，**多一行都算错**）。
  更稳的写法：边遍历边 `push_back` 出新层，长度天然精确
- **`memset` 三连坑**（**同一个函数栽三次**，值得单列）：
  | 日期 | 题 | 写法 | 后果 |
  |---|---|---|---|
  | 09-11 | LC 1094 | `memset(num, sizeof(num), 0)` | 参数顺序写反 |
  | 09-27 | LC 576 | `memset(memo, sizeof(memo), -1)` | 参数顺序写反 → 第三参变 `(size_t)(-1)` → **段错误 0xC0000005** |
  | 09-28 | LC 486 | `memset(memo, INT_MIN, sizeof(memo))` | 顺序对了，但 **INT_MIN 没法按字节填** → 实测填出 `0 0 0 0` |
  **两条规则**：① 参数顺序 `(指针, 值, 字节数)`；② **按字节填，只对 0 / -1 / 0x3f 安全**。

> **纪律**：成员容器在入口函数开头用 `assign()` / `clear()` 复位，
> 不要靠 `resize` 撞运气 —— 它只保证"元素个数"，不管"元素值"。

### 其他反复出现的问题

1. **递推式漏加当前元素** —— LC 304（漏 `matrix[i][j]`）、LC 974（`dp[i] += dp[i-1]` 漏 `nums[i]`）
2. **漏掉边界 / 空前缀** —— LC 974、LC 560 漏 `hash[0] = 1`（09-15 小测暴露）
3. **原地修改破坏原始数据** —— LC 1094 在循环里反复做前缀和，第二次操作全错
4. **概念混用** —— LC 40 组合题里加 `visit`，恒为 `false` 的死代码
   （排列用 `visit`，组合用 `start`）
5. **误用记忆化** —— LC 79：`memo[i][j]` 还取决于 `visit` 集合，
   状态描述不完整就不能记忆化。判断标准：**同一状态答案是否唯一**
6. **递归返回值不接** —— LC 79：单独写 `dfs(...)` 等于扔掉结果；
   也别用 `bool flag` 参数回传（按值传递改的是副本）
7. **状态定义与转移式不对齐** —— LC 53：定义写"以 i 结尾"，转移里却出现 `dp[i-1]`
   （它对应的子数组**不含 i**，与定义矛盾）→ 实际求成了"所有正数之和"。
   实测官方示例返回 12（应 6）。
   **纪律：转移式里出现的每一项，都必须能和状态定义对上。**
8. **C++ 接口记串** —— LC 994：`queue` 写成 `q.push_back(...)`（`push_back` 是 `vector` 的接口，
   `queue` 只有 `push`）。同名的还有 `front`/`pop` 别和 `stack` 混。
9. **返回值与声明类型错配** —— LC 994：函数声明 `int`，却写 `return false / return true`。
   `bool → int` 是**隐式转换，编译器不报错**，但结果永远是 0/1，从没返回过真正的答案。
   实测 9 个用例只对 2 个。
   **纪律：写完 `return` 自查「返回的东西类型对得上声明吗？它就是题目要的答案吗？」**
10. **多源 BFS 计时多 1** —— LC 994：`while` 里**无条件 `ret++`** 把第 0 层（初始源）
    也算成 1 分钟。判据：**层 = 时间，但第 0 层要减掉**（见「通用技巧」表的「多源 BFS」）。
11. **用了 C++17 语法（结构化绑定）** —— LC 542 旧版：`auto [x,y]=q.front();`
    这是 **结构化绑定，C++17 才有**。实测（g++ 8.1）：
    - `-std=c++11` **静默接受**（当非标准扩展），只有加 `-pedantic-errors` 才报
      `error: structured bindings only available with -std=c++17 or -std=gnu++17`
    - **考场 Dev-C++ 5.11（GCC 4.9.2）根本不支持** → 直接语法错
    **纪律：`auto` 后面不能带方括号；成对取值老老实实写 `.first / .second`。**
    本地能过 ≠ 考场能过 —— 自查用 `-pedantic-errors`。
12. **空输入没判空 → 空指针解引用** —— LC 102：`q.push(root)` 没判 `root == nullptr`，
    空树用例直接段错误（实测 exit code = 0xC0000005 / ACCESS_VIOLATION）。
    **入口第一件事就是判空**：树判 `root`、链表判 `head`、网格判 `grid` 为空/`grid[0]` 前先判。
    力扣**一定会**把空输入当测试点。
13. **同一个结构有两套约定时【混用】**（**用一套就得全套用**）
    - LC 695（09-18）：网格 DFS 有两套互斥的调用约定（「调用者标记」vs「自足式」）
      → 混用后 `dfs` **恒返回 0**（外层预标记 + dfs 又检查自己）
    - **LC 547（10-02）**：并查集有两套约定 —— 初始化用 `p[i] = -1`（负数约定），
      判根却用 `p[x] == x`（自指约定），数根又用 `e < 0`（负数约定）：
      ```
      find(0):  p[0] == 0 ?  -1 == 0  不成立  → p[0] = find(p[0]) = find(-1) → 越界【读】p[-1]
      unite():  p[find(x)] = find(y)         → p[-1] = ...                   → 越界【写】
      ```
      越界**写**破坏堆 → 实测退出码 **`0xC0000374` = HEAP_CORRUPTION（堆损坏）**。
      加探针后 4 个用例里错 2 个，且 `ret` 恒等于 `n`（孤立城市的用例"恰好"对，会掩盖错误）。
    - **判据**：**初始化 / 判根 / 循环条件这三处必须来自同一套约定**。
      换题/换人写之前，先问一句"**我现在用的是哪一套？**"
13. **建图那三行写错** —— 同一天连栽两次，全在建图：
    - LC 207：**方向反了**（把 `[a,b]` 建成 a→b）→ 因为"判环对方向不敏感"而**碰巧通过**
    - LC 210：`out[e[1]].push_back(e[1])` —— **推的值写成了桶的下标自己** → 建出自环，
      实测 4000 组错 **1822** 组（官方示例 1、2 全错，只有"无边"和"本来就有环"两个用例碰巧对）
    → 固化为 **「建图三问」**（见「模板」第 6 节）：**方向 / 桶 / 推进桶里的值**，逐条过完再提交。
14. **递归写成了调用【自己】** —— LC 2328：`flag += dfs(grid, i, j)` 应为 `dfs(grid, x, y)`。
    自调用 → **无限递归 → 栈溢出**（实测退出码 `0xC00000FD` = STACK_OVERFLOW，跑 `[[1,2]]` 就崩）。
    **纪律**：写递归时把"本层的参数"和"递归下去的实参"分开看 ——
    本层是 `(i,j)`，递归必须换成**邻居** `(x,y)`。
    （同日 LC 210 也有一次同类手滑：`out[e[1]].push_back(e[1])` 把"桶的下标"当值推了进去。）
