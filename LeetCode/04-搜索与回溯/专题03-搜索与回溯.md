# 专题03：搜索与回溯

> 2026-09-16 整理。覆盖 LC 46 / 47 / 39 / 40 / 51 / 79 六道题。
> 本专题的三个重点：**撤销选择的纪律**、**两种结果传递方式**、**"选择"的四种形态**。

---

## 一、一句话核心

**回溯 = DFS + 撤销选择。**

普通 DFS（遍历树、网格）走的路是单向的，不需要回头。
回溯是"试遍所有可能"，从一条分支返回时必须**把状态恢复原样**，才能干净地去试下一条。

```cpp
做选择;
dfs(下一层);
撤销选择;      // ← 这一行是回溯的灵魂
```

**少了撤销，程序不会崩、不会报错，只是答案错。** 这是最难查的一类 bug。

---

## 二、两种"结果传递方式"

这是最容易混的地方，也是 LC 79 卡住的原因。

| | **A 型：要全部解** | **B 型：只要一个解** |
|---|---|---|
| 返回类型 | `void` | `bool` |
| 结果怎么出去 | 成员容器 `ret` 累积 | **返回值一层层往上抛** |
| 找到一个之后 | 记进 `ret`，**继续**找下一个 | **立刻收工**，剩下的分支不看 |
| 例题 | 46 / 47 / 39 / 40 / 51 | 79 |

**判断用哪种**：题目说"返回**所有**方案"→ A；说"**是否**存在 / 返回**第一个**"→ B。

### A 型模板

```cpp
void dfs(参数) {
    if (出口) { ret.push_back(path); return; }
    for (每个候选) {
        if (不可选) continue;
        做选择;
        dfs(下一层);
        撤销选择;
    }
}
```

### B 型模板（"承接返回值"）

```cpp
bool dfs(参数) {
    if (出口) return true;              // 到底了，成功

    for (每个候选) {
        if (不可选) continue;
        做选择;
        bool 通 = dfs(下一层);          // ① 必须用一个变量接住
        撤销选择;                        // ② 先恢复现场
        if (通) return true;             // ③ 再往上抛
    }
    return false;                        // ④ 兜底：所有分支都不通
}
```

**四条铁律：**

1. **返回值不会自己冒出来，必须拿变量接住。** 写 `dfs(...);` 单独一行，等于把结果扔了。
2. **撤销要排在 `return true` 之前**（默认写法，见第四节）。
3. **兜底 `return false` 不能漏。** 循环跑完一个方向都没通，就是这条路不行。
4. **别想用参数把结果带回去。** C++ 参数默认按值传递，形参是副本，改副本不影响上一层（见第五节）。

---

## 三、"接返回值"到底在接什么

`dfs` 的返回值代表：**"从我这个位置出发，剩下的目标能不能达成。"**

- 返回 `true` → 这条路通了，整个调用链都要把它带回顶层
- 返回 `false` → 这条路不通，本层继续试别的候选

所以每一层要做的事，就是**把子问题的答案转交给父问题**。不接，等于信息在中间断掉了。

---

## 四、撤销和 `return` 的先后顺序

两种写法都能通过力扣：

```cpp
// 写法 1：先撤销，再上抛（推荐默认）
做选择;
bool 通 = dfs(下一层);
撤销选择;
if (通) return true;

// 写法 2：找到就直接返回，不撤销
做选择;
if (dfs(下一层)) return true;
撤销选择;      // ← 成功时这句被跳过
```

**写法 2 为什么也能对**：一旦成功，整条调用链都要 `return true` 一路退出，中途不会再读 `visit`，所以脏状态没机会被用到。竞赛里这个写法很常见。

**但写法 2 有严格前提**：**只有"找到一个就收工"的题能这么写。**

一旦题目变成下面任一种，写法 2 立刻给出错答案：

- 要**所有**解（成功之后还要接着搜）
- 找到之后**还要继续**（计数、求最优、找所有起点）
- 同一个对象**被调用第二次**（本地调试时最容易撞上）

**建议**：默认用写法 1。只有你能明确说出"我这么写，因为成功后一定整条链退出"时，才用写法 2。

## 五、参数是按值传递的

想通过参数把结果传回去，**必须用引用**。

```cpp
bool dfs(..., bool flag)   // 按值：每层拿到的都是副本，改副本不影响上一层
bool dfs(..., bool& flag)  // 按引用：改的是同一个东西，能传回去
```

**但 `bool` 返回的题目根本不需要这个 `flag`** —— 直接接返回值就够了。绕这条路的代价是多一个参数、多一份状态，还容易漏。

## 六、"选择"的四种形态

**看见题面就能定下来怎么写循环、怎么判约束。** 这是"信号词 → 工具"那份清单在回溯里的版本。

| 形态 | 每层的"选择"是 | 循环从哪开始 | 约束怎么判 | 例题 |
|---|---|---|---|---|
| **排列** | 选一个还没用过的数 | `0` | `visit` 数组 | 46 / 47 |
| **组合** | 选一个下标 ≥ `start` 的数 | `start` | 不需要（位置天然不重复） | 39 / 40 |
| **棋盘** | 这一行的皇后放哪一列 | `0` | 三个约束数组 | 51 |
| **网格** | 往上下左右哪一格走 | 4 个方向 | 越界 + 字符匹配 + `visit` | 79 |

### 排列 vs 组合：`visit` 还是 `start`

- **排列**：下标可以回退（第 3 个位置还能选第 1 个数），所以必须用 `visit` 记住"选过谁"。
- **组合**：下标只增不减（`start` + 下一层传 `i` 或 `i+1`），"选过谁"由位置本身保证，**不需要 `visit`**。

> **两个混用就会出现"死代码"**：组合题里加了 `visit`，它恒为 `false`，因为你循环里遇到的每个下标都还没被选过。

### 棋盘/网格的"约束数组"

- N 皇后：`col[c]`、`diag1[r - c + n]`（主对角 ↘，`+n` 避免负下标）、`diag2[r + c]`（副对角 ↙）
- 网格搜索：用 `visit` 数组，或**原地改写字符**（走过就改成 `'#'`，回溯时改回来）

**原地改写的前提**：改成的那个字符**绝不可能出现在合法数据里**。

## 七、去重：树层 vs 树枝

| | 含义 | 判据 |
|---|---|---|
| **树枝去重** | 一条路径内，同一个元素不能用两次 | `visit` 数组 |
| **树层去重** | 同一层的候选里，值相同的只能选第一个 | 排序 + 和相邻元素比较 |

**去重判据会随题型变形**，这是最容易照搬出错的地方：

```cpp
// 排列（LC 47）：层的边界是 0（每层候选都是全体）
if (i > 0 && nums[i] == nums[i-1] && !visit[i-1]) continue;

// 组合（LC 40）：层的边界是 start（每层候选从 start 起）
if (i > start && nums[i] == nums[i-1]) continue;
```

**判据的语义是固定的**："我和前一个值相同，而前一个**在本层还没被选走** → 我们俩是同一批候选，只用第一个。"

**变的是"本层的边界在哪"**：排列里是 `0`，组合里是 `start`。

## 八、记忆化搜索成立的前提

**只有一条：同一个状态，答案必须唯一。**

判断步骤：

1. 状态能被哪几个参数完全描述？
2. 这个答案会不会**还取决于"怎么走到这个状态"**？

LC 79 为什么**不能**记忆化：

| 需要知道的 | 进状态了吗 |
|---|---|
| 当前格子 `(i, j)` | ✅ |
| 匹配到 word 的第几个字符 | 传了 `position`，可以进 |
| **哪些格子已经被走过** | ❌ 只有 `visit`，没进状态 |

同一个 `(i, j)`，绕一圈过来和直接走过来，`visit` 里被占用的格子完全不同，能走的路也不同 → **"从 `(i,j)` 无解"这个结论换条路就不成立**。

而把 `visit` 集合也算进状态，状态数量是指数级的 —— 等于没有记忆化。

**LC 329（最长递增路径）才是记忆化的标准题**：状态就是 `(i, j)`，答案唯一，可以放心存。

> **记忆化不是"加个数组就快了"。先问：状态够不够描述这个局面？**

## 十、开写前的三句自问

每道题动笔前，把这三个答案写出来（不用长，一行）：

1. **A 型还是 B 型？**（要全部解，还是要一个解）
2. **每层的"选择"是什么？循环从哪开始？**（`0` / `start` / 列 / 方向）
3. **要哪些数组，最大下标各是多少？**（写不出公式就是没算）

第 3 条是今晚两次栽跟头的地方（LC 51 的 `dig2`）。
